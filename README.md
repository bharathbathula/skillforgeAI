# SkillForge AI

> **Job-Specific Resume Analysis, ATS-Oriented Evaluation, Skill-Gap Analysis & AI-Assisted Career Recommendations**

SkillForge AI is an academic full-stack mini-project that helps candidates evaluate a resume against a target job description. The system combines document parsing, structured information extraction, deterministic matching, transformer-based semantic similarity, ATS-oriented component scoring, skill-gap analysis, and an optional downstream AI-assisted recommendation layer.

The important architectural principle is that **the ATS-oriented score is not generated by a generative AI model**. The core evaluation is produced by the project's deterministic analysis services together with pretrained sentence embeddings from **`all-MiniLM-L6-v2`** and cosine similarity. The optional AI layer is used after the core analysis to provide practical suggestions such as skills to develop, project ideas, learning directions, and resume improvements. A deterministic rule-based recommendation fallback is also available.

---

## 1. Project Overview

### Problem

Candidates often find it difficult to determine whether a resume is aligned with a particular job. Important information such as skills, experience, education, projects, responsibilities, and qualifications may be expressed in different formats or terminology. Simple keyword matching can also miss semantically related statements.

SkillForge AI addresses these problems by providing a job-specific analysis workflow that:

- extracts relevant information from resumes and job descriptions;
- identifies explicit skill matches and skill gaps;
- evaluates experience, education, projects, responsibilities, keywords, semantic alignment, and formatting;
- produces an ATS-oriented score with a component breakdown;
- provides an interpretable report rather than a single unexplained number;
- optionally generates grounded career recommendations from the analysis results.

### Core Principle

```text
Resume + Job Description
          |
          v
Document Parsing & Structured Extraction
          |
          +-------------------------------+
          |                               |
          v                               v
Deterministic Analysis          all-MiniLM-L6-v2
          |                     Embeddings + Cosine
          |                               |
          +---------------+---------------+
                          |
                          v
                 Hybrid Evaluation
                          |
              +-----------+-----------+
              |           |           |
              v           v           v
          ATS Score   Skill Gaps   Job Alignment
                          |
                          v
             Optional AI Recommendations
                          |
                          v
                  Final Analysis Report
```

The recommendation layer is **advisory**. It does not replace the core analysis and does not modify the ATS score.

# 3. AI Architecture

The project intentionally treats generative AI as a **single downstream recommendation layer**, rather than making the complete application dependent on an LLM.

### Core analysis

The following remain independent of the generative recommendation provider:

- resume parsing;
- job-description parsing fallback;
- skill extraction;
- deterministic matching;
- experience evaluation;
- education evaluation;
- project analysis;
- responsibility matching;
- keyword analysis;
- semantic similarity using `all-MiniLM-L6-v2`;
- ATS-oriented scoring;
- skill-gap identification.

### Recommendation layer

The recommendation service can use an external provider when an API key is configured. It receives structured analysis information rather than the raw resume. The service is designed to produce:

- priority skills;
- project suggestions;
- learning directions;
- resume improvements.

If an external provider is unavailable, the system falls back to deterministic recommendations generated from the identified gaps.

### Important distinction

```text
Core Evaluation
    |
    +--> Deterministic scoring
    +--> all-MiniLM-L6-v2 semantic similarity
    +--> ATS score
    +--> Skill gaps
    |
    v
Optional Recommendation Layer
    |
    +--> Skills to develop
    +--> Projects to build
    +--> Learning direction
    +--> Resume improvements
```

The external AI layer **does not calculate or overwrite the ATS score**.

> Note: the repository contains provider integrations for Gemini, OpenAI, and Claude/Anthropic. They should be treated as optional provider implementations for the recommendation/AI layer, not as the mathematical ATS scoring engine.

### Architectural separation

The most important separation is:

**Core analysis:** deterministic + embedding-based.

**Recommendation layer:** optional AI-assisted guidance.

This allows the application to continue producing an ATS-oriented report even when an external AI provider is not configured or fails.

# 6. ATS-Oriented Scoring

The current ATS scoring service combines eight project-defined components:

| Component | Weight |
|---|---:|
| Skills Match | 25% |
| Experience Match | 20% |
| Responsibilities | 20% |
| Keyword Coverage | 10% |
| Semantic Similarity | 10% |
| Education Verification | 5% |
| Project Alignment | 5% |
| Formatting & ATS Readability | 5% |
| **Total** | **100%** |

The score is calculated from the project's analytical logic and the semantic similarity component. It is an **ATS-oriented compatibility indicator**, not a reproduction of any proprietary commercial ATS score.

Conceptually:

```text
Overall Score =
    0.25 Skills
  + 0.20 Experience
  + 0.20 Responsibilities
  + 0.10 Keywords
  + 0.10 Semantic Similarity
  + 0.05 Education
  + 0.05 Projects
  + 0.05 Formatting
```

The report also provides component scores so that candidates can understand why their overall alignment is high or low.

---

# 7. Semantic Matching

The semantic analysis uses the pretrained Sentence Transformer model:

```text
all-MiniLM-L6-v2
```

The model is used for **inference**. The project does not train the model from scratch.

Resume and job-description sections are converted into vector representations. Cosine similarity is then used to estimate semantic alignment between the representations.

```text
Text
  |
  v
Sentence Transformer
  |
  v
Embedding Vector
  |
  v
Cosine Similarity
  |
  v
Semantic Score
```

A TF-IDF-based fallback is available when the embedding service cannot use the transformer model.

# 8. Skill-Gap Analysis

Skill extraction is based on a curated technical skill taxonomy and normalized matching logic.

The system can identify:

- matched skills;
- missing skills;
- partial skill evidence;
- skill categories;
- evidence from professional experience;
- evidence from projects;
- skills merely mentioned in the resume.

This enables a more useful result than a single score. The candidate can see which skills are already demonstrated and which target requirements need additional evidence or development.

# 9. AI-Assisted Career Recommendations

The recommendation service is downstream from the ATS analysis.

### Inputs

The recommendation layer receives structured information such as:

- target role;
- matched skills;
- missing skills;
- skill score;
- experience alignment;
- detected gaps;
- formatting improvements.

Candidate PII and the raw resume are not intended to be sent to external recommendation providers by the recommendation service.

### Outputs

The service can provide:

1. **Priority skills** to develop.
2. **Project suggestions** that practice missing skills.
3. **Learning direction** for closing identified gaps.
4. **Resume improvements** based on detected weaknesses.

Example concept:

```text
Missing Skill: Docker
        |
        v
Priority Skill: Docker
        |
        v
Suggested Project: Containerized Backend Deployment
        |
        v
Learning Direction: Docker fundamentals -> containerization -> deployment
```

The system also contains a deterministic fallback so that recommendations can still be generated without an external AI API.

# 14. Database and Persistence

The project supports SQLite for straightforward local development and PostgreSQL for a production-oriented relational deployment.

Configuration is controlled through environment variables. The default configuration currently enables SQLite:

```text
USE_SQLITE=True
```

PostgreSQL can be enabled by setting `USE_SQLITE=false` and providing the PostgreSQL connection settings.

### Main entities

- `User`
- `Resume`
- `JobDescription`
- `Analysis`
- `SkillMatch`
- `ATSScore`

SQLAlchemy manages ORM access and Alembic manages schema migrations.

ChromaDB is separate from the relational database and is used for vector representations/retrieval where enabled.

# 15. Authentication and Security

The backend uses JWT authentication and bcrypt-based password hashing.

Important security practices:

- Do not commit `.env` files.
- Do not commit API keys.
- Use `.env.example` as the configuration template.
- Use a strong random `SECRET_KEY` outside development.
- Keep uploaded files outside source control.
- Do not expose production database credentials in the repository.

The recommendation service is designed to avoid sending candidate PII or the raw resume to external AI providers.

# 18. Analysis Pipeline

The main backend analysis endpoint performs the following high-level steps:

```text
1. Verify authenticated user and resume ownership
2. Obtain or create target job description
3. Extract resume text
4. Parse resume into structured data
5. Parse job description into structured data
6. Chunk resume and job-description sections
7. Index vector representations when enabled
8. Run deterministic ATS analysis
9. Run semantic similarity analysis
10. Combine component scores
11. Identify matched and missing skills
12. Generate optional recommendations
13. Persist ATS score and analysis details
14. Return final report
```

The recommendation step is downstream of the scoring step.

# 20. Project Evaluation Philosophy

The project should not claim an accuracy percentage, precision, recall, F1 score, or superiority over commercial ATS systems unless those values are obtained from a defined labeled evaluation dataset and reproducible experiment.

For the current prototype, the appropriate evaluation claims are:

- end-to-end functional completion;
- component-level score traceability;
- deterministic ATS calculation;
- semantic similarity behavior;
- skill-gap identification;
- recommendation fallback behavior;
- robustness across controlled edge cases.

# 21. Current Research/Project Contribution

The project's contribution is primarily a **hybrid system architecture and implementation** rather than training a new foundation model.

```text
Resume Parsing
      +
Structured Information Extraction
      +
Deterministic Competency Matching
      +
all-MiniLM-L6-v2 Semantic Similarity
      +
Component-Level ATS Evaluation
      +
Skill-Gap Analysis
      +
Optional AI-Assisted Career Recommendations
      =
Job-Specific Candidate Analysis Platform
```

The architecture deliberately avoids making an external LLM responsible for the core numerical evaluation. This makes the ATS result more transparent and allows the recommendation layer to be changed or disabled without redesigning the scoring engine.
